Part IV: Model building: no train/test split:

formula <- Y ~ DOSE + AGE + SEX + RACE + WT + HT + BMI

# Linear model
lm_model <- linear_reg() %>%
  set_engine("lm")

# LASSO (tunable)
lasso_model <- linear_reg(penalty = tune(), mixture = 1) %>%
  set_engine("glmnet")

# Random Forest (tunable)
rf_model <- rand_forest(
  trees = 500,
  mtry = tune(),
  min_n = tune()
) %>%
  set_engine("ranger") %>%
  set_mode("regression")

# Workflows
lm_wf <- workflow() %>% add_model(lm_model) %>% add_formula(formula)
lasso_wf <- workflow() %>% add_model(lasso_model) %>% add_formula(formula)
rf_wf <- workflow() %>% add_model(rf_model) %>% add_formula(formula)

Discussion: Overall, this exercise shows that more complex models like random forests can look much better at first (RMSE ~356), but that’s because they’re overfitting when evaluated on the same data. Once we use proper cross-validation, performance becomes more realistic (RMSE ~610), and the advantage of complex models disappears. LASSO ends up behaving like the linear model, and both perform similarly.

LASSO behaves like the linear model because the optimal penalty value is very close to zero. When the penalty is near zero, there is essentially no regularization, so the coefficients are not shrunk and the model is the same as ordinary linear regression. In this dataset, the predictors are already informative and not too noisy, so shrinking them does not improve performance. As a result, LASSO ends up giving the same results as the linear model.

In the end, it shows that while complex models can fit data really well, you need proper validation to trust the results otherwise, you’ll be overly optimistic about how well your model actually works.
